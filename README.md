# WakeLite

AstrBot 的轻量唤醒插件。在群聊场景下决定 bot 要不要对一条消息做出回复，7 个唤醒信号 + 群白名单 + 唤醒 CD + 复读过滤 + 多 bot 分流。

不引入 Pipeline/BaseStep 框架，不分阶段、不阻塞、不沉默检测、不黑名单。只回答一个问题：**这条消息要不要唤醒 bot？**

## 唤醒源

按代码判定顺序（便宜的先判，任一命中即唤醒并 return）：

| # | 信号 | 触发条件 | 配置项 |
|---|---|---|---|
| 1 | 人格名 | 消息含当前实际生效人格的 `name`，按概率决定 | `persona_name_prob` |
| 2 | 关键词 | 消息包含任一配置关键词，按概率决定 | `keyword_words` + `keyword_prob` |
| 3 | 概率 | 每条消息兜底随机唤醒 | `prob` |
| 4 | 答疑 | 消息的「提问意图」分数 > 阈值（请问/为什么/怎么等） | `ask_threshold` |
| 5 | 无聊 | 消息的「无聊表达」分数 > 阈值（好无聊/死群/有人吗） | `bored_threshold` |
| 6 | 兴趣 | 命中自定义兴趣词包，加权分数 > 阈值 | `interest_words` + `interest_threshold` |
| 7 | 相关性 | 消息与 bot 最近 N 条回复 TF-IDF cosine > 阈值 | `similar_threshold` |

每类智能唤醒都会在本轮 `extra_user_content_parts` 中追加临时提示。提示明确：历史中的其他用户发言，即使带有鲜明人物设定或固定口吻，也只是背景材料，不应被模仿或续写；模型应以当前生效的人设自然回应当前消息。该提示不会写入对话历史。

**配置项语义分两类**：
- **【概率类】**（`persona_name_prob` / `keyword_prob` / `prob`）：`0=关闭`，越大越易唤醒，范围 0-1
- **【阈值类】**（`ask/bored/interest/similar_threshold`）：`1=关闭`，越大越严，范围 0-1

## 辅助机制

- **群白名单**（`whitelist_groups`）：只有列表内的群聊走唤醒判定；不在列表的群完全不处理。
- **唤醒 CD**（`wake_cd`）：按会话 + 用户独立计时，CD 期内该用户在当前会话的所有判定都跳过。
- **指向他人过滤**：消息明确 @ 了他人或引用了他人（且没有任何指向自己的信号）时，跳过全部唤醒判定——用户显然在跟别人说话；@自己、@全体、引用 bot 自己、以及同时 @自己 的混合消息都照常判定；被引用消息的发送者平台未提供时不排除（避免漏唤醒）。
- **复读过滤**：用户消息与 bot 最近回复（去标点后）完全相同且长度 ≥ 4 字时拦截。chat_memory 源只比对该用户触发的回复；回退源没有发送者信息，仍比对全量；短句（好的/收到/谢谢）不参与判定。
- **拒绝回复工具**（`enable_reject_tool` 总开关，默认 false）：开启后仅在智能唤醒的本轮向 LLM 注入 `wakelite_decline_reply` 工具（可选参数 `reason`：一句放弃原因，仅写入 DEBUG 日志）。LLM 判断该话题实际不需要自己回复时（如用户明确在询问群里的另一个人、点名他人求助），可调用该工具放弃本轮回复，本轮不发送任何内容。@ 或指令唤醒不注入；哪些唤醒方式注入由 `reject_tool_scopes` 勾选（默认仅弱信号：概率/关键词/无聊/兴趣/相关性；人格名、答疑、跟随窗口默认不注入）。

## 唤醒跟随

用户唤醒 Bot 之后，它不会立刻回到待机，而是像一个人拿起手机刷群：**窗口内每条新消息都要考虑回不回**，但不再追踪某个特定用户。

窗口内**唤醒信号照常参与判定**（人格名/关键词/答疑等，命中即唤醒并重新计时）；信号全部未命中时，再按两个概率因子相乘兜底：

| 因子 | 含义 |
|---|---|
| 时间 | 从窗口开启算起，越往后概率越低 |
| 消息距离 | 自己上一条回复之后隔了多少条，越远概率越低，达到上限归零 |

两个因子共用一条曲线（`curve`），归一化到起点 1、终点 0（`constant` 恒 1，即不衰减，图中未画）：

![跟随概率曲线](https://cdn.jsdelivr.net/gh/W-Wolfycz/wakelite@main/assets/followup-curves.png)

两个因子是**相乘**关系：时间进度（从窗口开启算起）与消息距离进度（自己上一条回复后群友说了几句）各自查曲线得到一个系数，相乘即为本次回复概率。下图是四种衰减曲线对应的三维曲面（`constant` 恒 1、不衰减，未画入图中）：

![跟随窗口双因子曲面](https://cdn.jsdelivr.net/gh/W-Wolfycz/wakelite@main/assets/followup-surface.png)

配置组「跟随窗口」（`follow_up`）：

| 配置 | 含义 |
|---|---|
| `enabled` | 启用跟随窗口（总开关）；关闭时窗口完全不生效 |
| `window` | 窗口长度（秒）；0 = 不启用 |
| `gap` | 消息距离上限（条，0–100）；0 = 不启用距离因子 |
| `command` | 指令是否也进入窗口（默认豁免） |
| `prob` | 窗口起点概率（0–1）；`constant` 曲线下即整窗恒定概率 |
| `curve` | 曲线：`constant` / `linear` / `exponential` / `smooth` / `power`（先慢后快） |
| `allow_other_at` | 窗口内是否也响应「@他人 / 引用他人」的消息（默认不响应） |

语义细节：

- **总开关关闭时窗口完全不生效**（`follow_up.enabled`）；**任何唤醒都会开窗/刷新窗口**（「被唤醒了就进入玩手机状态」）；**指令是唯一默认豁免**，勾选 `command` 后才开窗。
- **唤醒源黑名单**（`blacklist_users`）：ID 填 `QQ`（所有群）或 `群号:QQ`（仅该群），勾选要屏蔽的唤醒源——人格名/关键词/答疑/无聊/兴趣/相关性/概率/跟随窗口（窗口的开启独立，但判定命中的唤醒与其他唤醒源同级）。
- 唤醒源留空 = 全部屏蔽；旧版「群号:QQ」列表、1.3.6 的 `follow_up_block_ids`、1.3.7 的 `follow_up.block_ids` 会在加载时自动合并迁移并写回配置。
- 消息距离的锚点是「自己上一条回复发出时的会话消息序号」（`on_decorating_result` 记录）；重启后锚点丢失时，该因子暂不惩罚，时间因子仍然生效。
- 概率命中的回复不注入唤醒提示与拒绝工具（属于自然续接），信号命中的轮次按原有规则处理。
- **窗口按 BOT 维度（UMO）独立**：先过窗口（有窗口直接按窗口逻辑判定），没窗口才走分流与唤醒；任何唤醒（含跟随窗口自身的概率命中）都会启动/刷新窗口。
- 窗口内**不参与多 bot 分流**（判定先于分流，窗口内必须接话）；窗口过期才恢复分流轮转。
- 窗口过期立即回退正常逻辑（信号 + 多 bot 分流 + 唤醒 CD）。
- 被复读过滤、指向他人过滤、用户黑名单优先拦截。

## 依赖

- **jieba**（必需）—— 答疑/无聊/兴趣/相关性都依赖中文分词
- **[chat_memory](https://github.com/W-Wolfycz/chat_memory) v1.0+**（可选，推荐）—— bot 历史回复的数据源。未安装或 `use_chat_memory=false` 时回退到 AstrBot 自带 history（回退源没有时间信息，不参与时间衰减）

## 安装

把本目录放到 AstrBot 的 `data/plugins/wakelite/`，重启或重载插件。依赖 `jieba` 会自动安装（见 `requirements.txt`）。

## 配置

26 个可见配置项，按相关性分组（WebUI 顺序一致；另有隐藏的迁移兼容项）：

### 日志
- `log_with_bot_id`（bool，默认 true）—— 日志前缀变为 `[WakeLite][platform:平台实例ID]`（如 `[WakeLite][platform:BOT1]`），模块名与平台实例标识并存，多 Bot 环境方便定位
- 日志等级在 AstrBot WebUI 插件详情页调整（DEBUG/INFO 等，运行期即时生效，无需重启），插件不再提供 debug 提级开关
- 旧版 `log_config` 配置组由 AstrBot 按新 schema 自动清理并注入新键默认值，旧开关值不会被继承；升级后请在 WebUI 确认日志前缀开关

### 准入 / 数据源
- `whitelist_groups`（list）—— 群号列表。空列表 = 所有群都不处理

- `group_bots`（list，默认空）—— 多 bot 分流配置（按群）。空 = 关闭分流。详见下方「多 bot 分流」段
- `use_chat_memory`（bool，默认 true）—— bot 历史是否走 chat_memory 插件
- `history_scope`（`group` / `user`，默认 `group`）—— 候选 Bot 回复的来源：`group` = 全量消息（全群所有用户触发的回复）；`user` = 对话轮（只看当前发送者触发的轮次；chat_memory 的 assistant 行 `user_id` 即被回复对象）。回退到 AstrBot 自带历史时不支持按发送者过滤
- `bot_msgs_maxlen`（历史条数上限，int，默认 15，最大 50）—— 候选 Bot 回复的逻辑**条数**上限（建议 10-30）。chat_memory 的 `limit` 同义：一轮里的多条物理行会先合成为一条逻辑回复再计条数

### 人格名 / 关键词唤醒
- `persona_name_prob`（float，默认 0.5）—— 命中人格名后的唤醒概率。人格名每次实时解析（AstrBot 内部已缓存 persona 列表），无插件级缓存
- `keyword_words`（list，默认 `["BOT", "机器人", "萝卜子"]`）—— **每行一个独立关键词**（如各种对机器人的称呼），命中任一即按概率唤醒；与兴趣词包不同，不做累计打分，不区分大小写，留空则不生效
- `keyword_prob`（float，默认 0.5）—— 命中任一关键词后的唤醒概率，0 = 关闭

### 兜底 / 文本判定
- `prob`（float，默认 0）—— 概率唤醒，建议 0.01-0.1
- `ask_threshold`（float，默认 0.5）—— 答疑唤醒阈值
- `bored_threshold`（float，默认 0.5）—— 无聊唤醒阈值

### 兴趣 / 相关性
- `interest_words`（list，默认 `["咖啡 手冲 拉花", "摄影 镜头 构图"]`）—— **每行一个兴趣词包**，包内相关词用空格分隔；命中越多、词越长分数越高，需超过 `interest_threshold` 才唤醒（与单关键词的即时概率判定不同）
- `interest_threshold`（float，默认 0.5）—— 兴趣唤醒阈值
- `similar_threshold`（float，默认 0.5）—— 相关性唤醒阈值

### 全局
- `wake_cd`（秒，默认 0.5）—— 同一会话中同一用户两次唤醒的最小间隔，0 = 关闭
- `blacklist_users`（template，群聊白名单之后）—— 唤醒源黑名单：ID 填 `QQ` 或 `群号:QQ`，选择屏蔽的唤醒源（含跟随窗口）；旧配置自动迁移
- `follow_up`（配置组）—— 跟随窗口：`enabled` 启用开关、`window` 窗口长度、`gap` 消息距离上限（0–100）、`command` 指令是否豁免、`prob` 起点概率、`curve` 曲线、`allow_other_at` 是否响应 @他人
- `enable_reject_tool`（bool，默认 false）—— 拒绝回复工具总开关，详见「辅助机制」
- `reject_tool_scopes`（多选，默认 probability/keyword/bored/interest/similarity）—— 勾选哪些唤醒方式允许 Bot 主动放弃回复；未勾选的唤醒方式即使总开关开启也不注入该能力

## 历史与相关性如何工作

WakeLite 不会把群聊自动切成“前段/中段/后段”，也不会把历史用户消息送进相关性计算。它只做以下步骤：

1. 根据 `history_scope` 取得 Bot 回复候选（全量消息，或当前发送者触发的对话轮）；
2. 候选数量按**条数**受 `bot_msgs_maxlen` 截断；
3. 把当前用户消息分别与每条候选 Bot 回复计算当前窗口的 TF-IDF cosine，再按候选年龄做时间衰减（越新权重越高，年龄约 10 分钟时权重降为一半）；
4. 取加权最高相似度，与 `similar_threshold` 比较。

例如：

```text
用户 A：手冲咖啡水温多少合适？
Bot：浅烘建议 90 度上下，深烘可以低一些。
用户 B：今天天气不错。
Bot：确实适合出去走走。
用户 A：那磨豆粗细呢？
```

- `history_scope=group`：最后一条会同时与两条 Bot 回复比较，通常第一条取得更高分；
- `history_scope=user`：最后一条只与由用户 A 触发的第一条 Bot 回复比较；
- 用户 B 的“今天天气不错”本身不会进入比较，只有 Bot 对它的回复可能成为候选。

`history_scope` 只决定候选回复来自全群还是当前用户；TF-IDF 负责给这些候选计算相关程度，时间衰减负责让越新的候选越容易触发唤醒。旧话题的候选必须文本上足够接近才能盖过衰减。

## 多 bot 分流

`group_bots` 按群配置哪些 Bot 参与分流。每行一个 Bot 实例：

- `self_id`（或 `self_id:`）—— 该 Bot 在**所有群**参与分流
- `self_id:群号` —— 该 Bot **仅在该群**参与分流

`self_id` 就是 bot 自身的 QQ 号（bot 发消息时，其他 bot 看到这条消息的 sender_id 就是它）。每个群的分流池 = 配置中「所有群启用 + 本群显式启用」的 Bot；同一群配置多个 Bot 时按消息哈希轮流响应，单 Bot 群 100% 响应。

**示例**：

```json
["10001", "10002:123456789", "10003:987654321"]
```

- `10001` 在所有群参与分流；`10002`、`10003` 只在各自指定的群参与。

**分流规则**：

| 信号 | 是否参与分流 |
|---|---|
| 人格名唤醒 | ❌ 所有 bot 都跑（叫谁谁响应） |
| 关键词/概率/答疑/无聊/兴趣/相关性 | ✅ 按当前群的分流池哈希到唯一 bot |
| 复读过滤 / 唤醒 CD / 群白名单 gate | ❌ 所有 bot 都跑 |

**多 bot 状态语义**（影响调参决策）：

- **唤醒 CD 按 UMO + 用户计**：不同平台实例、群聊和私聊之间不共享 CD，避免用户在一个群触发后影响另一个群
- **历史范围可配置**：`history_scope=group` 时同一 UMO 内不同用户可接续 Bot 话题；`user` 时只看当前发送者触发的 Bot 回复。不同平台实例仍按各自 UMO 隔离
- **配置错误处理**：本 bot 不在当前群的分流池 → 该 bot 的所有阈值/概率判定都跳过；格式错误（self_id 为空）→ 该项被忽略并打 warning；旧 `bots` 配置不再读取

## 设计取舍

- **不引入 Pipeline/BaseStep**：只有一个 hook + 一个判定函数
- **不持久化状态**：内存里的 `_last_wake` 重启即清；运行中会惰性清理过期项
- **不实现黑名单 / 阻塞 / 指令屏蔽 / 沉默检测 / 防抖**：交由其他插件处理
- **不重复实现 @ 唤醒 / 引用唤醒**：AstrBot 自带，本插件只补充「智能唤醒」
